# LupiraAssistant — agent notes

- BFF pattern: ~/Nextcloud/Familj/DevOps/Guides/bff-pattern.md
- Shared frontend conventions: ~/Nextcloud/Familj/DevOps/Guides/frontend-estate.md (repo-specific deviations below).
- **Monorepo** (npm workspaces, mirrors LupiraCal): `apps/mobile` (the canonical surface), `packages/domain` (`@lupira/assistant-domain`), `packages/tokens` (`@lupira/assistant-tokens`), `src/LupiraAssistantBff`. No web SPA; deferred in `docs/roadmap.md`, the tokens package is already shaped for it. BFF deployment: DevOps `WebApps/lupira-assistant-web`.
- **BFF**: proxy only (no merged contract, no `openapi/`), mobile Authentik JWT bearer (`lupira-assistant`). Upstreams: assistant-api, comms-api, health-api. `exposed.json` groups: `operations`, `anonymous` (assistant-api OIDC enrollment legs, browser, no bearer; announced via `X-Forwarded-Prefix`), `device` (health ring/summaries ingest at the upstream path, key gate `UseLupiraBffDeviceKeyGate`).
- **One origin — the BFF**, device ingest included. A new upstream endpoint the app calls needs an `exposed.json` line. `API_PRESETS` in `config/env.ts` holds the origin per preset.
- **Offline-first.** The inbox is one doc in the `@danbro96/lupira-sync-engine` kernel (`sync/inbox-module.ts`: snapshot feed over `GET /inbox`, `reduce` hides the gesture's item, `replay` posts the ack with `Idempotency-Key` = `clientActionId`, hold key = item id). Gestures are kernel outbox ops: optimistic, crash-safe, backed off on transient failures, parked on a 4xx (item stays hidden; visible in the Developer screen's sync state). Reads use `mirrorQuery(['assistant.inbox'])`.
- **Layering** (eslint-plugin-boundaries v7): `domain → data → sync → state → ui`, with `config` as a leaf. `@danbro96/lupira-*` imports are allowed per layer (tokens everywhere, http from data up, the feedback/diagnostics-log/oidc leaves from data up, the Paper kit and diagnostics screens from ui). `apps/mobile/eslint.config.mjs` is the plain `mobile()` preset of `@danbro96/lupira-config-eslint`.
- **The headless cone must stay UI-free.** `index.ts` registers `state/background-sync-task` at module top level, loaded in the OS's bare JS context at cold start: `defineSyncTask` with a prepare step that loads the auth session. The cone is the engine and the auth store; `useColors` is imported only from `ui/`, keeping Paper out of it.
- **API clients are generated**: orval → `src/data/api/generated/` (never hand-edit), `client: 'fetch'`, body-only (`includeHttpResponseReturnType: false`), not react-query hooks — the engine calls them headlessly and the app owns its query keys.
- **Palette**: the core palette and spacing come from `@danbro96/lupira-tokens-core`; the app's own semantics (`pending`, `failed`, `banner*`, `toast*`) extend it in `@lupira/assistant-tokens` and ride on the Paper theme (`createPaperThemes` from `@danbro96/lupira-expo-paper`) beside the MD3 colours.
- **`ui/screens/ThreadScreen.tsx` bubbles stay bespoke `View`s.** No `Card`/`Surface`: the day-break/`previous`-row coupling and `maxWidth: '85%'` alignment are load-bearing. The FlashList is chronological; row spacing lives in the row, since FlashList positions items absolutely and ignores `gap`.
- **Shared UI kit, feedback, diagnostics, OIDC, HTTP, sync kernel and query plumbing** come from LupiraPlatform (`@danbro96/lupira-expo-paper`, `-expo-feedback`, `-expo-diagnostics`, `-expo-oidc`, `-http`, `-sync-engine`, `-expo-query`, `-expo-sqlite`; `~/Nextcloud/Familj/DevOps/Guides/platform-packages.md`). Auth is `createAuthStore` (`-expo-oidc/authStore`; `onAccountChange` wipes the engine and the query cache). Reads go through `@danbro96/lupira-expo-query`: `createAppQueryClient` (persisted roots `assistant`, `comms`), `connectOnlineManager`/`connectFocusManager`, `useOnline`, `onlineQuery` for grant status, preferences and connectors; the archive stays a Zustand store. In-app `data/api/mutators.ts`: `apiFetch` = `createBearerMutator` with `decorate` adding the dev-mode `X-Dev-User`; `deviceKeyFetch` = the same mutator with a `DeviceKey` header, NDJSON body passthrough, 401 → `DeviceKeyInvalidError`. Auth ports stay in the app.
- No reanimated: no gestures to animate, and it would move the Expo fingerprint. Paper 5 is pure JS, so it does not.
- **Test floor**: `domain/` fully covered, plus `state/` store transitions and the sync module on `openNodeDb`. UI is verified on a device (Developer screen). `packages/tokens` holds only constants, so it has no test script; adding logic there means adding one.

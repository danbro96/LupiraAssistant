# LupiraAssistant — agent notes

- BFF pattern: ~/Nextcloud/Familj/DevOps/Guides/bff-pattern.md
- Shared frontend conventions: ~/Nextcloud/Familj/DevOps/Guides/frontend-estate.md (repo-specific deviations below).
- **Monorepo** (npm workspaces, mirrors LupiraCal): `apps/mobile` (the canonical surface), `packages/domain` (`@lupira/assistant-domain`), `packages/tokens` (`@lupira/assistant-tokens`), `src/LupiraAssistantBff`. No web SPA; deferred in `docs/roadmap.md`, the tokens package is already shaped for it. BFF deployment: DevOps `WebApps/lupira-assistant-web`.
- **BFF**: proxy only (no merged contract, no `openapi/`), mobile Authentik JWT bearer (`lupira-assistant`). Upstreams: assistant-api, comms-api, location-api, health-api. `exposed.json` groups: `operations`, `anonymous` (assistant-api OIDC enrollment legs, browser, no bearer; announced via `X-Forwarded-Prefix`), `device` (health/location ingest at the upstream path, key gate `UseLupiraBffDeviceKeyGate`).
- **One origin — the BFF.** A new upstream endpoint the app calls needs an `exposed.json` line. `API_PRESETS` in `config/env.ts` holds the origin per preset.
- **Offline-first.** Assistant gestures apply optimistically → inbox cache + a queued ack on the pending-acks stream (crash-safe monotonic `seq`), drained by `sync/sync-engine`.
- **Layering** (eslint-plugin-boundaries v7): `domain → data → sync → state → ui`, with `config` as a leaf. `@danbro96/lupira-*` imports are allowed per layer (tokens everywhere, http from data up, the feedback/diagnostics-log/oidc leaves from data up, the Paper kit and diagnostics screens from ui). `apps/mobile/eslint.config.mjs` is the plain `mobile()` preset of `@danbro96/lupira-config-eslint`.
- **The headless cone must stay UI-free.** `index.ts` registers `sync/background-upload-task` at module top level, loaded in the OS's bare JS context at cold start. `useColors` is imported only from `ui/`, keeping Paper out of the cone.
- **API clients are generated**: orval → `src/data/api/generated/` (never hand-edit), `client: 'fetch'`, not react-query — reads come from the BFF and the inbox cache.
- **Palette**: the core palette and spacing come from `@danbro96/lupira-tokens-core`; the app's own semantics (`pending`, `failed`, `banner*`, `toast*`) extend it in `@lupira/assistant-tokens` and ride on the Paper theme (`createPaperThemes` from `@danbro96/lupira-expo-paper`) beside the MD3 colours.
- **`ui/screens/ThreadScreen.tsx` bubbles stay bespoke `View`s.** No `Card`/`Surface`: the day-break/`previous`-row coupling and `maxWidth: '85%'` alignment are load-bearing. The FlashList is chronological; row spacing lives in the row, since FlashList positions items absolutely and ignores `gap`.
- **Shared UI kit, feedback, diagnostics, OIDC and HTTP plumbing** come from LupiraPlatform (`@danbro96/lupira-expo-paper`, `-expo-feedback`, `-expo-diagnostics`, `-expo-oidc`, `-http`; `~/Nextcloud/Familj/DevOps/Guides/platform-packages.md`). The mutators (`apiFetch` with 401→refresh on every method and the dev-mode `X-Dev-User`), auth ports and the SQLite handle stay in the app.
- No reanimated: no gestures to animate, and it would move the Expo fingerprint. Paper 5 is pure JS, so it does not.
- **Test floor**: `domain/` fully covered, plus `state/` store transitions. UI is verified on a device (Developer screen). `packages/tokens` holds only constants, so it has no test script; adding logic there means adding one.
